You are tagging app store reviews of the Canva mobile editor (iOS and Android) for a weekly product review. Read ONE review and return ONE tag for it, following these rules exactly.

## Categories

**product_flaw** - Something that exists in the mobile editor does not work the way a user can reasonably expect: it fails, crashes, freezes, lags, loses work, or hides information the user needs until it is too late (for example, only revealing that an element is Pro at download time). A review is still a flaw when the user also suggests a fix; judge the problem, not the suggestion.
Example (product_flaw):
"there's no way to tell which fonts and graphics are Pro until you try to save. I'm on free and ended up redoing my whole invite. put a crown on them or something"
Why: it ends with a suggestion, but the core problem is that the editor hides which items are Pro until the user tries to save, and the user lost work.

**feature_request** - The user wants a capability the mobile editor does not have yet, often one that exists on desktop. Nothing is broken; something new would have to be built. Wording like "can't find" or "doesn't work" can still be a request when the thing was never in the mobile editor.
Example (feature_request):
"The new editor looks great but I can't find my brand kit anywhere. I have to type in our hex codes by hand every time. Please add brand kit to mobile"
Why: "can't find" sounds like a bug, but brand kit is not in the mobile editor and the user asks for it to be added.

**neither** - The review has no product flaw and no feature request: praise, general comments, or wishes about pricing and which plan includes a feature (a business decision, not something the editor team builds or fixes).
Example (neither):
"Really like the new editor, it's way faster to find templates. Only wish the background remover was on the free plan, even a few uses a month would be nice"
Why: it is praise plus a wish to change what the free plan includes. Nothing is broken and nothing new needs building.

## Deciding rules
- Flaw or request? Ask: would fixing a bug make this user happy (product_flaw), or would Canva have to build something new (feature_request)?
- Paywall: being surprised by Pro content too late is a product_flaw. Asking for a Pro feature to be free, on its own, is neither.
- Use neither only when the review has no flaw and no request.
- Judge only the review text. Do not guess facts the review does not state.

## One winner
Return exactly ONE tag per review. If the review raises more than one issue, pick the winner like this: choose the category that comes first in this order: product_flaw, then feature_request, then neither. If several issues share that category, choose the one with the highest impact score. Ignore the other issues; do not mention them in the tag.

## Impact score (for product_flaw and feature_request)
Score how badly the winning issue hurts the user, from 1 to 10:
- 9 to 10: the app crashes or freezes, the user loses work, or the user cannot finish the task in the app at all.
- 7 to 8: a core task fails repeatedly or only works with a workaround, or a core tool is unusable.
- 4 to 6: noticeable friction (lag, confusion, surprise paywall, extra manual steps), but the task still gets done.
- 1 to 3: minor or cosmetic, or a nice-to-have.
For neither, leave theme and impact_score empty.

## Theme
A short lowercase label naming the feature and the problem or wish, such as 'pdf export fails', 'text box lag', 'pro items not marked', 'brand kit on mobile'. Use the same wording for the same problem every time.

## Quote
Copy ONE sentence from the review that shows the winning issue, exactly as written: same spelling, capitals, punctuation and spacing. Never reword, shorten, merge sentences or fix typos. If you cannot copy it exactly, choose a different sentence.
